# Requirements

`SPEC.md` is listed in `.gitignore`, so Tailwind does not scan it for class names. Keep it that way.

This Tailwind CSS v4 project has three settings pages (`index.html`, `notifications.html`, `billing.html`) that share `src/input.css`. They were built for left-to-right layout with physical utilities such as `ml-4`, `pl-2`, `left-0` and `text-left`. Convert the whole project to Tailwind's logical utilities so it works in Arabic, right-to-left, and still lays out exactly as before in left-to-right.

- On every page, the language must be Arabic (`lang="ar"` or `lang="ar-JO"`) and the direction right-to-left, set on the `<html>` element.
- The layout must follow `<html dir>` alone: when only the `dir` attribute on `<html>` changes between `rtl` and `ltr`, the page must mirror exactly: every element's box mirrors across the page, and its padding, borders, corner radii, scroll padding and text alignment swap sides. Only the left-to-right islands below keep their content left-to-right (their position still mirrors).
- Change only `class` attributes and `src/input.css`; do not add, remove, reorder or re-tag elements.
- Convert, do not redesign: with `dir="ltr"` on `<html>`, every element must keep the position and size it has in the original project (to within 2 px), and its padding, borders, corner radii, scroll padding and text alignment on each side. Do not hide, clip, shrink, scale or move anything.
- Use logical utilities such as `ms-*`, `me-*`, `ps-*`, `pe-*`, `start-*`, `end-*`, `border-s`, `border-e`, `rounded-s-*`, `rounded-ss-*`, `float-start`, `scroll-ps-*` and `text-start`. Do not use any physical Tailwind utility (`ml-*`, `mr-*`, `pl-*`, `pr-*`, `left-*`, `right-*`, `border-l*`, `border-r*`, `rounded-l-*`, `rounded-tl-*` and the other corner forms, `float-left`, `float-right`, `scroll-pl-*`, `text-left`, `text-right` and the like), not even behind a variant such as `md:`, `hover:`, `rtl:` or `ltr:`, and no physical CSS property (`left`, `right`, `margin-left`, `padding-right`, `border-left-width`, `border-top-left-radius`, `float: left`, `text-align: left` and the like) anywhere in the compiled CSS, including `@apply`, arbitrary values, hand-written rules in `src/input.css` and `@import`ed styles. Logical properties (`margin-inline-start`, `inset-inline-end`, ...) are fine.
- Some content must stay left-to-right in the Arabic pages: the elements that already carry `dir="ltr"` (the email address, the webhook URL, the IBAN and the masked card number). Keep their direction left-to-right and their text starting at their left edge.
- Keep every page free of sideways scrolling on a 360 px wide screen.
- All styling must come from Tailwind classes and `src/input.css`. Each page must link only `dist/app.css`, with no `<style>` element, no inline `style` attribute, no `<script>` (not even one that removes itself), no `on*` event handler attribute and no other stylesheet. The grader rebuilds `dist/app.css` from your source (`tailwindcss -i src/input.css -o dist/app.css`) and ignores the `dist/` you leave behind, so editing `dist/app.css` by hand has no effect. Tailwind scans every file in the project for class names, so do not leave a file in the project (a conversion script, notes) that mentions physical class names: they would be compiled into `dist/app.css`.
- Keep every `data-testid` attribute (and its element, visible) and all text, including the Arabic text, as it is.
