# v1.0 run, November 2026: Claude Code and Codex CLI on a local 9B model

> **Read this first.** One small local model (9B parameters, 4-bit). These numbers say nothing about frontier agents and are not a leaderboard entry. Most variants ran once; Track A ran 3 times. Per-variant differences are noise. Only pooled numbers mean anything, and even those are small samples.

## 4. Failure modes

Real trials, quoted from the Harbor logs. The grader line is from `verifier/verify.log`.

**1. Arabizi: kept the request, broke the guard rail (Claude Code, `format-price-currency`).** The prompt ends "w ma t5arrib line_text" ("and don't break line_text"). The agent changed `line_text` anyway:

```text
def line_text(name, amount, currency='JOD'):
    return f"{name}: {format_price(amount, currency)}"
```

Grader: `FAIL line_text_signature: expected line_text keeps its name and arguments`. The English trial of the same task changed only `format_price` and passed.

**2. Arabizi: misread "with tax" (Codex, `extract-add-tax`).** The prompt asks for a helper that returns the amount "ma3 dareebe" (with tax). The agent wrote a helper that returns the tax alone:

```text
def add_tax(amount):
    return round(amount * 0.16, 2)
```

Grader: `FAIL helper_behaviour: expected add_tax adds the tax and rounds to 2 decimals`. (The English trial of this task timed out, so this is not a clean pair.)

**3. Arabizi: no edit at all (Claude Code, `loop-for-to-while`).** Prompt: "biddi azabit il function. 3'ayerha min for loop la while." The agent opened no file and made no tool call. It wrote a generic tutorial in Arabic about a made-up `print_numbers` function. Grader: `has_while: false`, `no_for: false`.

**4. Arabizi: right fix, only in chat (Codex, `page-items-off-by-one`).** The agent read `paging.py`, then answered in chat with the correct line (`start = (page - 1) * per_page`) but never wrote the file. Grader: `FAIL first_page: expected page 1 gives the first items`. Its reply mixed French and non-Jordanian Arabic ("El problème ...").

**5. RTL: a logical property in the wrong place (Claude Code, `rtl-nav-fix`, English).** The agent replaced `padding-left: 48px` with `inset-inline-start: 48px`. That property positions an element; it does nothing to padding on a static one. Grader: `no_physical_css: .hero {padding-left: (unset); padding-right: 16px}`, and the sign-in link was still on the wrong side.

**6. Timeout: cut mid-edit (Claude Code, `rtl-react-chat`, Jordanian).** The agent ran exactly 450 s. Its last log entry was a thought: "أحتاج أيضاً لضبط padding الـ composer ليكون متوازناً" ("I also need to balance the composer padding"). It had already edited `Chat.jsx` and `styles.css`. The grader scored the partial work: `no_physical_css` (inline `margin-right`, `text-align: right`) and `no_horizontal_overflow: scrollWidth=372 clientWidth=360`.

Pattern: in the Arabizi failures, the agent usually understood the topic of the request. It failed on the details (a guard rail, "with tax") or on acting at all (answering in chat instead of editing the file).

## 5. What this run may claim (fixed 2026-11-22, before results)

Written before any v1r2 result was read, so the results cannot shape it. Later changes go below as dated amendments, never as edits to this section.

- **Allowed:** "the pipeline grades a local agent end to end on the current prompts"; per-track pass counts; the failure examples in section 4.
- **Not allowed:** any claim that Jordanian or Arabizi prompts make agents worse or better. With 4 paired Track A tasks and 1 try each, one trial swings parity by 25 to 100 points, far above any real effect. Parity numbers are printed but labelled "not significant, N = 4, 1 try".
- **Timeouts and setup errors** count as failures and are listed separately, per agent and per prompt language, so a language that is slower to set up is not mistaken for a language the agent misreads.
- **Published whatever it shows.** If every variant fails or every variant passes, that is the result.

Amendments:

- 2026-11-22: Track A got 2 more tries per variant (`v1rep`), so section 3 pools 3 tries, not 1. The "not allowed" rule still holds: N is still 4 tasks.

## 7. What this does and does not show

It shows the pipeline works end to end: two agent harnesses ran all 16 tasks on a local model, and every trial was graded by deterministic checks in a container or a real browser, with no AI judge. The failures are the kinds the benchmark was built to catch: guard rails broken, answers left in chat, RTL half fixed with the wrong CSS. It does not rank agents or models. A 9B model at half the normal time limit is far from how these agents are used. A frontier-model run needs a budget, which is the board's decision.
